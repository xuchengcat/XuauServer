# VS010 后台与 SSID VLAN 能力核查

时间：2026-09-28 15:52–15:55（Asia/Shanghai）。

接续此前 VLAN 设计调查，目标是确认桥接模式的 unwifi 能否按 SSID 分别接入 VLAN 2（ULA + NAT66）和 VLAN 20（公网 IPv6），两网段通过服务器双向互通。

## 实测结果

设备：联通 VS010，管理地址 `192.168.2.30`，现场邻居 MAC `58:95:d8:1a:83:1a`。使用用户提供的管理密码，按设备登录表单的用户名 `user` 和 Base64 密码编码提交一次认证，收到 302、认证 Cookie 和 stok。密码、Cookie 和令牌不写入记录。

请求直接发往设备 HTTP 地址，绕过 NPM 和环境 HTTP 代理。

| 检查 | 结果 |
|---|---|
| 管理登录 | 成功建立认证会话 |
| 认证首页 | 只取得顶部菜单，12 秒时请求超时，未取得配置正文 |
| 无线设置 `/admin/wifi` | HTTP 200，正文仅 1845 字节，在退出链接处截断；curl 退出码 18 |
| 高级设置 `/admin/advance` | 同上，未取得任何高级设置表单 |
| 局域网设置 `/admin/lan` | 同上，未取得 LAN/VLAN 配置 |
| 隐藏入口 `/api/set/telnet` | HTTP 响应头为 200，但正文包含 `Status: 500 Internal Server Error` 和错误页 |
| 静态 `common.js` | 完整读取；没有找到证明每 SSID VLAN 绑定的配置或接口 |
| TCP 22 / 23 | 均为 Connection refused，SSH/Telnet 未开放 |
| 服务器 br_lan IPv6 | 保持 `fc00:192:168:2::100/64`，当前地址没有 tentative/dadfailed 标记 |

各配置页面在相同位置截断，说明问题涉及共用后台页面；具体原因仍未知。静态资源版本参数为 `Dec11093955CST2024`，不能等同于已读取到完整固件版本。

## 对方案的影响

**SSID 绑定 VLAN 能力仍未能确认。** 页面异常不等价于不支持；也没有足够证据保证单台 VS010 能同时承载两个无线 VLAN。桥接模式和交换机支持 VLAN 本身不能补足这一条件。

暂按原设计中的条件分支处理：

- 若以后取得每 SSID VLAN ID、bridge 绑定和上联 tagged/native 配置证据，再采用单 AP 双 SSID 方案，并通过终端实测验证。
- 在没有这些证据时，可以使用两个桥接 AP，分别接交换机 access VLAN 2 和 access VLAN 20。VS010 整台接入某个 access VLAN 时，其普通桥接无线设备整体归入该网段；这不能实现同台 AP 内的两组划分。

本次没有重启、刷机、启用远程服务、提交网络配置或应用服务器候选方案。此前服务器 PD /62 提议与候选配置离线检查的结果参见《设计与迁移计划》，本次没有重新验证或确认 PD 租约。
